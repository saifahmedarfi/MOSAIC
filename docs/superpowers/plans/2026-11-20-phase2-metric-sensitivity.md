## Review Focus

Five conditions the spec implies, that a reasonable person would expect to work, and that no
task's happy path exercises. Each has a test added to the task that owns the code.

1. **A run whose entire population scores zero** (Phase 1's `valsartan_smarts` did this for all
   27 of its runs). Its Pareto front is empty or a single origin point; hypervolume must be
   `0.0`, not `NaN` and not a crash. → Task 1.
2. **Zero seed variance within a cell.** `SD_pool` becomes 0 and `z` divides by it. Phase 1 hit
   exactly this: `np.std` of 50 identical `0.3`s is ~1e-17, not 0, so an absolute-zero check
   does not catch it and the quotient is garbage rather than an obvious error. → Task 1.
3. **All three backbones exactly tied** on a metric. The argmax is undefined and must be
   reported as "no stable winner" rather than silently resolved by array order. → Task 2.
4. **A metric that is constant everywhere** (degenerate). It must be excluded by name *before*
   BH correction, never consume FDR budget. Phase 1 lost four features this way and the
   handling is inherited. → Task 3.
5. **Fewer than 5 oracles surviving the reproduction gate.** The sweep must refuse to launch
   rather than proceed on an underpowered set. → Task 4.

- [ ] **Step 3: Implement `winner_replication` and `criterion_0` in `src/phase2_stats.py`**

Each of the `n_boot` draws: resample the oracle list **once with replacement, and use that same
oracle list for all three backbones**; then, within each selected (oracle, backbone) cell,
resample its seeds with replacement independently. Recompute `metric_score` on the resampled
frame and take its argmax **inside the draw**. `replication` is the fraction of draws whose
argmax equals the point-estimate argmax. An exact tie in the point estimate yields
`winner = None` and `stable = False`.

The shared oracle list is the load-bearing detail: Phase 1 measured an across-oracle AUC SD of
0.229, so an independent per-backbone resample would leave that main effect uncancelled and drive
every draw's argmax to near-chance. `phase1_stats.flip_pairs` resamples each cluster
independently and is **not** the precedent to copy here.

`criterion_A`'s replication counts draws in which **both** argmaxes are re-selected inside the
draw and still differ — not draws in which a frozen pair of winners happens to differ.

`criterion_B`'s per-metric `p` tests the observed fraction against the `2/3` expected when
within-oracle winners are unrelated, by the hierarchical bootstrap. A metric with no finite
variation across the frame goes into `degenerate_metrics` and is excluded from `per_metric`
**before** `bh_fdr` is called, so it cannot consume FDR budget.

`criterion_C` reads the gap in the §5.2.1 unit, so `threshold` is `C_THRESHOLD` with no unit
conversion. When `c0["state"] == "one"`, the AUC comparator is the per-oracle AUC argmax rather
than `cA["winner_auc"]`.

`phase2_verdict` implements spec §6's table exactly, and the table governs wherever prose
disagrees with it. Branch on `c0["state"]` first. Then: `"neither"` → `BENCHMARK-INSENSITIVE`;
`"one"` → C decides (`METRIC-RESOLVING` if it passes, `COSMETIC` if not); `"both"` → **A before
C** — A failing gives `METRIC-ROBUST` whatever C says, because when the two metrics agree on the
winner there is no ranking change whose magnitude C could measure.
