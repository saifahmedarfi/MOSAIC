# Phase 3 Pareto-Front Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a three-arm `graph_ga` experiment that tests whether NSGA-II selection over verified component vectors produces a better Pareto front than scalarized selection at equal oracle budget, and what that costs on `auc_top10`.

**Architecture:** `phase0_lib.py` is frozen, so the Pareto operator cannot be patched in; instead `src/phase3_pareto.py` reimplements the `graph_ga` loop with a pluggable selection rule, and the experiment carries three arms — vendored `graph_ga` (anchor), reimplemented scalar (control), reimplemented NSGA-II (treatment). All statistics reuse `phase2_stats`'s common unit and shared-oracle bootstrap by import. A 45-run pilot sets the two thresholds, which are then frozen into a hashed pre-registration before the 405-run sweep exists.

**Tech Stack:** Python 3.11, numpy 1.26.4, rdkit, PyTDC 1.1.15, scikit-learn 1.2.2 (pinned), torch cu126. Vendored `mol_opt` for `crossover.py`/`mutate.py`. jupytext percent format. No pytest — plain script test harness.

**Spec:** [docs/superpowers/specs/2026-11-22-phase3-pareto-optimization-design.md](../specs/2026-11-22-phase3-pareto-optimization-design.md)

- `scikit-learn == 1.2.2` exactly. On ≥1.3 TDC's `drd2`/`jnk3` load without raising and return `0.0` for every molecule.
- `numpy == 1.26.4`, Python 3.11.
- Every threshold is in **pooled-seed-SD z units already** (`metric_score` returns `mean_o z`); never multiply by an SD again.
- `METRICS = ("auc_top10", "hypervolume", "front_size")`. `front_coverage` is **excluded** as collinear with `front_size`.
- `N_BOOT = 10_000`; oracle list resampled **once per draw, shared across all three arms**; seeds resampled independently within each cell.
- Grid: 9 oracles × 3 arms × seeds, `explore_mid`, budget 1000. `GAConfig(population_size=100, offspring_size=200, mutation_rate=0.01)` — unchanged from Phases 0–2.
- Zero-component molecules are **excluded before non-dominated sorting**, in both mating pool and survival (spec §4.1.1).
- Component vectors may be computed **only for molecules already in `oracle.mol_buffer`** (spec §3.5).
- `δ_P`, `ε_Q` and the seed count come from Stage A. No task chooses them. The seed count is bounded to **[20, 30]**: a faithful reimplementation fails Criterion F at 15 (spec §6.3).
- **Environment prerequisite:** tasks 1–2 need only numpy; tasks 3–7 need rdkit and pandas. Build in the `lce` environment.

## Review Focus

1. **An oracle generation where every molecule has a zero component** — `positive_mask` empties the candidate set and NSGA-II has nothing to rank. `sitagliptin_mpo` scores only 59% of probes non-zero, so this is reachable. Expected: fall back to scalar selection for that generation and record the fallback, never crash or return an empty population. → Task 2.
2. **A generation producing no valid offspring** — `phase0_lib` breaks out only after `gen > 50`. A reimplementation that breaks immediately diverges from the anchor and fails Criterion F for the wrong reason. → Task 3.
3. **Budget exhaustion mid-generation** — `BudgetedOracle` caps and returns `0.0` for over-budget molecules, whose true components are non-zero. Expected: the treatment arm sees only `mol_buffer` members, so a capped molecule is never component-scored. → Task 3.
4. **Fronts of size 1 or 2** — 20% of Phase 2 runs had a buffer front ≤2; `amlodipine_mpo` averages 1.8. Expected: `crowding_distance` returns all-infinite without NaN, and the criteria compute rather than emitting NaN. → Tasks 1 and 4.
5. **Exactly duplicate component vectors** — `BudgetedOracle` dedupes SMILES, but distinct molecules can share a component vector. Expected: `non_dominated_sort` ranks exact ties into the same front and terminates. → Task 1.

    # the margin sits inside the quantile, not beside it.
